# Catalog schema v13: note-owned encrypted attachments

Version `0x000d` adds `private_note_attachments` to the Rust-owned SQLCipher catalog. Both filenames and payload bytes stay inside SQLCipher; no plaintext path, disk thumbnail cache, media-original row, network URL loader, or new encryption format is introduced.

Each row has a parent `note_id` foreign key with `ON DELETE CASCADE`, a note-scoped 16-byte `attachment_id`, validated filename, sniffed MIME and `data BLOB`. The compound primary key is `(note_id, attachment_id)`. Files are limited to 8 MiB each, 16 MiB combined, and 32 rows per note. Filenames are basenames of at most 240 UTF-8 bytes without path separators, colon, control characters, or dot components. Native import validates these rules independently of the host, including unique IDs and MIME signatures. PNG, JPEG, GIF, WebP and PDF signatures receive their safe MIME; other files remain `application/octet-stream`. MIME is not proof of a decodable or harmless document, and preview decoding has separate resource bounds.

Attach/remove commit the row, note revision, monotonic update time and catalog generation together under the displayed revision. They cannot modify a trashed note. A portable package import commits note source, metadata, search row and every file in one transaction; failures expose no partial note. Attachment identities remain stable so `attachment:<32 lowercase hex>` Markdown sources survive import without rewriting. Files are owned by one note; detach removes its bytes. Trash retains them for restore and explicit export. Permanent purge and retention expiry cascade their removal. SQLCipher secure-delete, WAL and encrypted backup behavior apply as for note text; deletion does not revoke older user-held backups.

Fresh catalogs install v13. Existing v12 vaults first install the authenticated `MIGRATING` descriptor `(12,13,migration_generation=12)`. One SQL transaction creates the checked table and advances the version. Failure rolls back table, marker and version together. Unlock resumes before or after that SQL commit, checkpoints, and installs the authenticated active descriptor. Prior steps remain sequential. Restore migrates older catalogs before publishing the descriptor; future schemas are refused without downgrade.

Full encrypted backups include attachment rows in the catalog snapshot. Selective encrypted archives copy saved note source and all attachment bytes atomically into the selected note's fresh identity while preserving attachment IDs. No media synchronization or sharing row is created. A plaintext note export with files is the portable `.churnote` JSON package described in [ABI 5.0](../interop/FFI_CONTRACT.md#625-local-private-notes-abi-50), bounded to 24 MiB. A note without files keeps exact `.md`/`.txt` export behavior. ABI 5 adds an attachment count to the note control record; all native callers must ship together and reject other majors.

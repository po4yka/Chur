# Catalog schema v9: local private notes

Version `0x0009` adds local editable notes inside the existing SQLCipher database. It does not add a media class, object container, sync operation, or sharing grant.

## Tables

`private_notes` is a STRICT table with these fields:

| Field | Meaning |
| --- | --- |
| `note_id` | Unique non-null 16-byte opaque identifier generated by Rust |
| `revision` | Positive compare-and-swap token |
| `title` | UTF-8 text, at most 256 bytes |
| `body` | UTF-8 text, at most 262144 bytes |
| `created_ms`, `updated_ms` | Nonnegative Unix milliseconds in the supported SQLite integer range |
| `pinned` | Boolean `0` or `1` |
| `deleted_ms`, `expires_ms` | Both absent for active notes; both present in Trash |

The table's internal rowid maps each note to `private_note_search`, an FTS5 table over title and body with the `unicode61` tokenizer. Ordering and expiry have fixed indexes. Table, column, and index names contain no user data. FTS pages remain inside the same encrypted database. Secure-delete is enabled for catalog cells and for this FTS table; it does not remove historical backups or promise physical erasure.

## Transactions and bounds

Create, save, pin, unpin, Trash, Restore, and purge commit their row/search changes and catalog-generation advance together. New notes start at revision 1. Mutations of an existing note require its exact revision. Identical save/pin operations preserve revision and generation. Timestamps do not move backwards on edit. Purge removes both the live row and FTS row; only trashed notes can be explicitly purged.

A catalog holds at most 10000 notes including Trash. Note title/body reject NUL. Search accepts at most 256 UTF-8 bytes and 32 whitespace-separated terms. User terms become escaped literal prefixes; they cannot inject FTS syntax. Pages hold 1–100 summaries and truncate body previews to 160 Unicode scalar values. Complete bodies are returned only by the get/save/change surfaces.

A keyset cursor is 65 bytes: catalog generation u64, query fingerprint 32 bytes, pinned u8, updated time u64, and note identifier 16 bytes. Integer fields use big endian. The fingerprint uses the registered `CHUR\x00PRIVATE-NOTES\x00QUERY\x00V1` tag over the query bytes and Trash flag. It detects query/generation mismatch; it is not a keyed authorization token. The application binds cursors to its unlocked session and never persists them.

## Migration and backup

Fresh catalogs install v9. Existing v8 catalogs use the authenticated descriptor migration protocol. The schema step creates both note tables and their indexes, then records version 9 in one transaction. Interrupted migration resumes before or after that transaction without accepting a partial schema. The supported version chain remains contiguous.

The portable backup's encrypted catalog snapshot includes these tables. Restore runs the normal schema migration before installation. Notes remain in the selected identity. Earlier clients reject an unsupported catalog version. Existing media formats, public Notes files, and wire sync/sharing records are unchanged.

## Local ownership

Only a valid open session can access notes. Kotlin checks the expected session generation inside its repository mutex for each call. Native operations resolve the session's catalog; no note field carries a public path or a second database location. Notes are not projected as media objects and no sync worker publishes them.

# Catalog schema v14: note organization and recovery

Version `0x000e` adds four SQLCipher tables: `private_note_organization`, `private_note_history`, `private_note_history_blobs`, and `private_note_history_files`. Folder names, tags, historical Markdown/plain text, filenames, and original file bytes stay inside the encrypted catalog. No plaintext history file or thumbnail cache is created.

Organization is note-local: one optional folder and at most sixteen exact, case-sensitive tags. Labels are trimmed, nonempty, at most 64 UTF-8 bytes, and contain no control characters. Empty folder means unfiled. Tags are sorted and deduplicated, stored as a bounded canonical JSON string array. No folder hierarchy, global folder identity, or cross-vault association exists. Queries apply exact folder/tag predicates before keyset pagination; cursors bind both filters and the catalog generation.

Every changed source save, attachment addition/removal, or organization edit first snapshots the previous committed revision in the same transaction. A no-op save creates no snapshot. A snapshot retains title, body, explicit format, pin state, organization, monotonic update timestamp, and attachment identities/metadata. All historical file references point to note-owned encrypted BLOB rows; byte-identical originals share one BLOB across revisions. Text edits do not duplicate attachment bytes. A note retains at most twenty previous snapshots and 64 MiB of deduplicated historical file bytes. Oldest snapshots are evicted until both limits hold, then unreachable BLOB rows are erased. Current attachments retain their independent 8 MiB/file, 16 MiB/note, and 32-file limits. Retention is bounded recovery, not an indefinite audit log.

Restore requires an active note and its displayed current revision. It reads and validates the selected snapshot, retains the displaced current state, and commits exact source, organization, file identities, and original bytes as a new monotonic revision. The selected version can be restored even when it is the oldest version evicted by the restore's own retention pass. Restoring preserves current creation time, uses a monotonic update time, updates full-text search, and bumps catalog generation atomically. Concurrent changes are rejected without partial mutation. Trash retains current and historical data; source recovery requires restoring the note from Trash first. Permanent purge and expiry cascade all four tables and their files. SQLCipher secure-delete applies; user-held older backups remain independent copies.

Full encrypted backup/restore includes the tables in the authenticated catalog snapshot. Selective encrypted archives copy organization, all retained source snapshots, and each unique historical file exactly once (at most 64 MiB). Import assigns a fresh note identity and a monotonic destination-local revision sequence, while preserving attachment identities so Markdown references remain exact. History cannot be smuggled through an unencrypted portable `.churnote` export: that explicit export continues to contain only current source and files.

Fresh catalogs install v14. Existing v13 vaults install the authenticated `MIGRATING` descriptor `(13,14,migration_generation=13)` before the atomic DDL/version transaction. Failure rolls back tables, migration marker, and recorded version together. Unlock resumes on either side of the SQL commit and finishes the authenticated descriptor transition. Full restore sequentially upgrades previous versions before publication; future catalog versions are refused without downgrade. Existing v13 notes start with no organization and empty history; snapshots begin with the next actual edit.

The additive workspace commands use the existing note attachment control entry point and ABI 5 record layout; all structured outputs retain the 1 MiB preflight capacity. See [FFI contract](../interop/FFI_CONTRACT.md#625-local-private-notes-abi-50).

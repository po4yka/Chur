# Markdown notes

Public Notes and the selected vault's private notes use the same source editor and offline preview. Their stores, access rules, backup behavior, and draft lifecycle remain independent.

## Format and editing

New notes use Markdown. Public JSON v1 and private catalog v11 notes migrate as **plain text**. The format control changes interpretation without changing the body. Format is persisted; private format-only changes require the saved revision.

Source is authoritative: preview never serializes over it. The editor supports headings, emphasis, strikethrough, inline/fenced code, nested lists, quotes, reference links, GFM tables and task lists. Formatting commands edit the selection or selected lines. List continuation, indentation, find/replace, outline, bounded undo/redo and Ctrl/Cmd shortcuts work in source mode. Preview task checkboxes update the original source token. Code highlighting is local.

The dialect is the renderer's CommonMark/GFM parser, pinned with the application. This is a source editor with preview, not a WYSIWYG rich-document editor. Footnotes, math and arbitrary rich objects are not promised as visual-editing features; unsupported syntax remains available in source and exact-body Markdown export.

Managed images use `attachment:<32 lowercase hex digits>` references and render from the open note's own attachment store. Unmanaged images remain descriptive source references. There is no network image loader, arbitrary file-path resolver, CDN, WebView, script execution or automatic URL fetch. OCR integration, drawing, recording, organization and synchronization remain separate features. External HTTP/HTTPS/mail links require confirmation before opening another application; other URI schemes are inert. HTML cannot execute in Compose preview.

## Files

Import `.md`/`.markdown` with the system picker. Input must be valid UTF-8, contain no NUL and fit within 256 KiB. Body bytes are not trimmed or normalized; the filename supplies a title bounded to 256 UTF-8 bytes. Private import creates a session draft requiring Save. Picker callbacks are invalidated on disposal/session change; private pickers use the existing bounded host-activity lifecycle.

Markdown export writes **exact UTF-8 body bytes**, without inserting a title, BOM or newline. It uses `.md` and `text/markdown`. Plain text export remains `title + LF + LF + body` with `.txt`. Public export uses the system file destination. Private export continues through the native saved-revision operation, deliberate plaintext warning, cancellation, cleanup and selected-session checks. When a private note has files, its deliberate plaintext export writes a portable `.churnote` package containing the saved source and all attachments; its filename, MIME and exact export size reflect that snapshot. Encrypted archives and backups retain format, original source and attachment bytes.

## Durability and privacy

Public cache state advances only after persistence succeeds. Failed writes retain the editor draft for retry. Back offers save/discard; Save and leave waits for persisted content acknowledgement. Public pinning is available in the editor and reflected in list order.

Private Save remains explicit. Lock, panic, identity change, disposal or process loss clears unsaved session state. Rendering, undo, find/replace and outline use neither saved-instance state nor public persistence. Copy/Cut remain disabled. Undo is route-owned and bounded; retained saved versions have the separate durable lifecycle below. Managed strings and platform layout/input copies do not provide secure erasure.

Storage contracts: public JSON v4 (v1/v2/v3 migrate with empty organization/history; v1/v2 have no attachments) and [private catalog v14](../format/CATALOG_SCHEMA_V14.md). Private notes require breaking native ABI 5.0. Catalog upgrades use authenticated migration; old clients reject the newer catalog/ABI.

## Images and files

Use **Add image or file** in either editor. Each note can own 32 files, up to 8 MiB each and 16 MiB combined. Filenames are validated basenames of at most 240 UTF-8 bytes. MIME types are sniffed from the bytes, not trusted from a picker or extension. PNG, JPEG, GIF and WebP have static local previews; PDF, SVG, HEIC and other files remain attachments with no active embedded viewer. Original bytes are retained for export even when preview is unavailable. Decoding rejects dimensions above 16,384 on either edge or 64 million pixels and produces at most 384 pixels per edge. Repeated Markdown references share a bounded per-preview decode job; caches are route-owned and dropped on disposal/lock. When one paragraph repeats the same image URL with different descriptions, inline preview uses the generic accessible label “Image”; every original description remains intact in the Markdown source.

Public attachment payloads live under an app-private public store directory with random opaque storage keys. Catalog references are published only after payload writes succeed. The metadata commit and cache publication finish together even if the editor is disposed; failed imports retain the previous state. On Android, each JSON and payload write goes to a temporary file, is synced, renamed into place, and then the directory is synced. A failed directory sync does not fail the write, because the rename already published it. A process kill can leave a temporary file, or a payload that no committed state references. When the store first reads a JSON file that parses, it removes these leftovers: the JSON temporary, payload temporaries, and payloads that no current note or retained version names. A JSON file that cannot be read, or that is missing, causes no removal. Public files are **unencrypted** and follow the public shell's platform-backup policy. Public source edits preserve the latest attachment list, including when an older autosave was queued before an add/remove operation. Notes containing only files are retained.

Private attachment metadata and BLOB bytes are encrypted in the selected SQLCipher catalog. Add/remove operations require its current session and saved note revision. Save text changes before managing private attachments; adding a file is an explicit durable action, while an inserted Markdown reference remains an unsaved text edit until Save. Plain-text notes retain files without inserting Markdown syntax. Trash keeps files; permanent note purge deletes their rows transactionally. Removing a file preserves source references, which can then be edited or removed. Full backups and selective encrypted archives carry the files; copied/imported notes retain their note-scoped attachment identifiers. No file is copied to the public store or plaintext cache to preview it. Bounded owned input/read arrays are cleared after consumer completion; managed strings and pixels still have the memory limitations described above.

**Save file** exports an individual attachment through the system destination picker. Private files use the same explicit plaintext warning, saved-revision/session checks, native output operation and destination cleanup as whole-note export. **Export note package** exports the current public draft and all files. Private **Export package** uses the existing plaintext warning, saved-revision check, native destination, cancellation and cleanup flow; **Encrypted archive** keeps the same content encrypted.

Use **Import package** in either note list for an explicit import into that store. A private package import commits its source and all files together; it does not create an unsaved text-only draft. Packages up to 24 MiB are validated before publication. Malformed input, unsupported versions, invalid UTF-8/Base64, unsafe names, duplicate identifiers, MIME mismatches and resource-limit violations are rejected. Imports never extract paths or fetch a referenced URL. The same attachment ID in another note cannot overwrite that note's files. See the [portable format](../format/NOTE_PACKAGE_V1.md).

## Organization and recovery

Both lists offer **Folders and tags** filters. Each note has at most one flat folder label and sixteen tags, with at most 64 UTF-8 bytes per label. Labels are trimmed and case-sensitive; `Work` and `work` are distinct. Tags are entered one per line, so commas inside a label are preserved. An empty folder clears its assignment; empty filters include all folders/tags. Apply organization after saving the current text. Folder/tag filters combine with text search and Trash; private filtering happens in SQL before pagination and is part of the cursor identity.

**Version history** retains up to twenty previous committed versions per note, including exact source, format, pin state, folder/tags and original attachment bytes. Distinct historical payloads are bounded to 64 MiB per note, including files also referenced by the current version. Oldest versions are pruned when either bound is reached. Unchanged saves do not consume history. Public text-only autosaves within a 60-second window share the first pre-edit snapshot while every current edit is still persisted; the next window creates a new checkpoint. Pin, format, organization, file and recovery operations keep distinct snapshots. Private explicit saves retain each changed committed version. Browsing history is read-only; confirm **Restore version** to make a previous version current. Restoration creates a new revision and retains the displaced current version within these bounds. Public history previews show the first 4000 characters; restoring always includes the complete source and files.

Public **Trash** saves the latest editor text before moving the note, with files and history, to a separate list. **Restore note** returns it to active notes; **Delete permanently** requires confirmation and removes all its retained versions and payload references. Public history remains unencrypted alongside the public notes. JSON v4 permits at most 1000 notes including Trash and 32 MiB of serialized metadata/source/history; writes exceeding these bounds fail without replacing the previous committed store. Autosaves from an editor predating recovery cannot overwrite a restored version or recreate a note purged during that process; Android recreation retains the recovery epoch with the public route.

Private history, organization and historical BLOBs live in SQLCipher v14, survive lock/reopen, full encrypted backup and selective encrypted archive import, and are erased with permanent note purge. Archive import gives notes fresh identifiers and local revision numbers. History screens, label fields and late results obey the existing session/identity/lock boundary and never use saved-instance state. Private unsaved drafts remain session-only; this feature retains committed versions and does not autosave private draft text.

`.churnote` v1 remains an explicit transfer of the current source and current files. It does not transfer folder/tag organization, pin state, Trash or retained history. Use encrypted backup/archive for private recovery history. Removing a current attachment keeps its historical payload recoverable until the last referencing version ages out or the note is permanently purged.

# AstraCrypt reuse study for Chur

> **Status:** Experimental research; recommendations are not approved product scope

Date: 2026-10-16

## Decision brief

AstraCrypt is most useful to Chur as a reference for a broader personal vault: documents, captured material, private text, and deliberate export. It offers few missing foundations for Chur's existing media vault. Retain Chur's Rust-owned storage and session boundary. Implement selected user tasks through that boundary.

The three research workstreams covered product flows, privacy/authentication, and technical integration. Their combined recommendation is:

| Order | Candidate | User value | Relative effort | Decision |
| --- | --- | --- | --- | --- |
| 1 | Documents and arbitrary file storage | Keep PDFs, contracts, and other selected files beside private media | Large | Best next product expansion; separate storage from document viewing |
| 2 | Capture followed by vault import | Save a receipt or photograph without a manual gallery round trip | Medium to large | Prototype only after defining plaintext and camera trust boundaries |
| 3 | Private text records | Keep confidential notes inside the vault | Medium to large | Add a private object type; preserve public Notes as a separate surface |
| 4 | Structured batch export | Save a selected album to one chosen directory | Medium | Useful bounded extension to current export sinks |
| 5 | Audio artwork | Recognize audio content in the library | Medium | Optional media polish; retain waveform support |
| 6 | Operation notification with Cancel | Monitor long operations from the system surface | Medium; large if restartable | Conditional on session and background policy; no implicit unlock extension |
| 7 | Recent-import shortcut | Reach new material quickly | Small | Reuse an existing query; add only if navigation needs it |
| 8 | Breadcrumbs for future hierarchy | Navigate deeper document collections | Medium to large | Require an actual hierarchy use case first |
| 9 | Calculator public shell | Choose a useful alternate public utility | Medium | Later; preserve the documented visible vault entry |
| 10 | Quick Settings lock | An additional system lock control | Medium | Lower priority; normal background locking already exists |
| 11 | Encrypt a copy without library import | Prepare a portable encrypted transfer | Large | First assess existing backup/sharing; avoid a second format |
| 12 | Profile, crypto selectors, ZIP carrier tool | Limited fit with the current product | Variable | Do not add to the current scope |

These are product and engineering judgments from source comparison, not usage statistics or delivery estimates. The first three expand scope. The fourth is a smaller experiment if the goal is to improve the current media product. Existing release gates still take precedence: [ROADMAP](/Users/npochaev/GitHub/Chur/ROADMAP.md:9) records independent review and physical-device evidence gaps. This study does not close them.

## Product opportunities in detail

### 1. Documents and arbitrary files

AstraCrypt's creation sheet includes an unrestricted Add action, `onAdd("*")`, beside photo/video/audio choices: [CreateNew](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/sheet/CreateNew.kt:94). Its type mapping includes Text and Other: [FileUtilImpl](/Users/npochaev/GitHub/AstraCrypt/features/files/data/src/main/java/io/gromif/astracrypt/files/data/util/FileUtilImpl.kt:53). This is useful for PDFs, records, contracts, and other non-media files.

Chur's current Android import sheet offers photos/videos and audio: [ChurRoutes](/Users/npochaev/GitHub/Chur/apps/androidApp/src/main/kotlin/dev/po4yka/chur/android/ChurRoutes.kt:548). Its [MediaImporter](/Users/npochaev/GitHub/Chur/shared/app/src/commonMain/kotlin/dev/po4yka/chur/app/MediaImporter.kt:83) requires a successful codec probe before beginning import. Adding a wildcard picker alone would not deliver document support. Generic blob storage in a core is also distinct from a complete document workflow.

Proposed smallest slice: selected file import, encrypted original/name/type, a generic file tile, details, explicit export, and a clear unsupported-preview state. Add bounded PDF preview as a separate slice. Retain Rust ownership of metadata and storage; review canonical media-class/derivative contracts before introducing new types. Use the same Android/iOS behavior requirements, with native pickers at the host boundary. Local OCR is a possible later extension already listed in [Chur's roadmap](/Users/npochaev/GitHub/Chur/ROADMAP.md:159); this research found no basis for attributing OCR to AstraCrypt.

Acceptance before release: a file with an unknown or misleading MIME type remains intact through import/export; unsupported preview does not fail storage; lock clears filenames and preview state; cancellation and low-space failure preserve the original; Android and iOS can restore/export the same stored object.

### 2. Capture followed by import

AstraCrypt's Scan action obtains an output URI, launches capture, and imports the result: [FilesScreen](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/FilesScreen.kt:152). The contract is Android `TakePicture()`: [Scan](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/util/contracts/Scan.kt:8). This is an external camera handoff. It does not establish OCR, page-edge detection, multipage scanning, or capture confined to the vault process.

The reusable task is: open the vault, capture material, and commit it through the existing import path. For Chur, decide between a clearly disclosed external-camera handoff and capture inside the app. An external camera must see plaintext and may retain its own data; an app-owned temporary file alone cannot prove otherwise. Do not label that path a private camera.

Acceptance before release: specify where plaintext exists; exclude app-owned capture scratch from backup and gallery indexing; remove abandoned scratch on cancel, failure, lock, and process recreation; grant the narrow required URI access and revoke it when possible; define what happens if the vault locks during capture. Camera-return exceptions must not silently preserve an unlocked session. Use a neutral error when a captured file cannot be imported.

### 3. Private text records

AstraCrypt has actual note create/read/update/delete flows in [OverviewNoteViewModel](/Users/npochaev/GitHub/AstraCrypt/features/notes/presentation/src/main/java/io/gromif/notes/presentation/overview/OverviewNoteViewModel.kt:43). Its [notes repository](/Users/npochaev/GitHub/AstraCrypt/features/notes/data/src/main/java/io/gromif/notes/data/repository/RepositoryImpl.kt:37) encrypts/decrypts note fields when an AEAD is selected. The editor limits are 64 title characters and 1000 text characters: [OverviewScreen](/Users/npochaev/GitHub/AstraCrypt/features/notes/presentation/src/main/java/io/gromif/notes/presentation/overview/OverviewScreen.kt:62). It is a simple text editor, not a rich document system.

Chur already has functional public Notes, search, and editing: [NotesScreens](/Users/npochaev/GitHub/Chur/shared/app/src/commonMain/kotlin/dev/po4yka/chur/app/notes/NotesScreens.kt:61). The new opportunity is a separate encrypted text object inside the private vault. Keep its content, search data, drafts, and identity out of the public Notes store. Do not carry an optional unencrypted mode into the private record type. A minimal editor can use the existing Rust object lifecycle, but mutable drafts, replacement/versioning, and search need explicit contracts.

Acceptance before release: public Notes remain accessible without a private session and never enumerate private records; private text and drafts disappear from UI/semantics on lock; private text never enters ordinary platform backup or logs; save failure retains a recoverable draft only under a defined encrypted policy. Avoid automatically copying secrets into the clipboard or enabling rich attachments in the first slice.

### 4. Navigation and organization

AstraCrypt has a folder breadcrumb row with navigation to an ancestor: [FilesBackStackList](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/list/FilesBackStackList.kt:29), [BrowseActionsFactory](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/model/action/factory/BrowseActionsFactory.kt:17). This is a useful interaction reference if Chur later introduces nested document collections. Do not adopt a single-parent file tree to implement album membership: an object in several albums must not be copied or moved merely to match a folder UI. Breadcrumbs alone do not justify changing the catalog.

AstraCrypt's recent list is ten latest IDs, ordered descending: [FilesDao](/Users/npochaev/GitHub/AstraCrypt/features/files/data/src/main/java/io/gromif/astracrypt/files/data/db/FilesDao.kt:74). It is recently added material, not recently viewed history. Chur already supports `IMPORT_DESC`: [ChurVault](/Users/npochaev/GitHub/Chur/shared/core-ffi/src/commonMain/kotlin/dev/po4yka/chur/ffi/ChurVault.kt:1444). A shortcut to this query is a small navigation option; it needs no new tracking subsystem and must stay inside the private session.

### 5. Standalone encrypted transfer

AstraCrypt's Tink Lab supports key creation/loading/saving and separate text/file workflows: [KeyViewModel](/Users/npochaev/GitHub/AstraCrypt/features/tink-lab/presentation/src/main/java/io/gromif/tinkLab/presentation/key/KeyViewModel.kt:38), [TextViewModel](/Users/npochaev/GitHub/AstraCrypt/features/tink-lab/presentation/src/main/java/io/gromif/tinkLab/presentation/text/TextViewModel.kt:37). The [file worker](/Users/npochaev/GitHub/AstraCrypt/features/tink-lab/presentation/src/main/java/io/gromif/tinkLab/presentation/work/TinkLabFilesWorker.kt:122) streams encryption/decryption to a chosen external directory.

The potentially useful task is “create an encrypted copy for transfer without adding it to my library.” First assess whether Chur's portable backup and collection sharing already satisfy it. Exposing raw keysets, AEAD menus, and associated-data entry would add recovery and interoperability burdens. A new transfer format requires a recipient/key-delivery model and restore validation, not just an Encrypt button. Keep this later than the existing media workflow and do not make the normal vault require crypto configuration.

No inspected evidence establishes an advantage over Rust-owned session invalidation. This is an architectural comparison, not a full security audit or a finding that Tink itself is defective.

## Patterns to reject or redesign

1. **False successful import outcomes.** AstraCrypt [ImportUseCase](/Users/npochaev/GitHub/AstraCrypt/features/files/domain/src/main/java/io/gromif/astracrypt/files/domain/usecase/actions/ImportUseCase.kt:31) catches every `Exception` per item without reporting it, including coroutine cancellation exceptions. [ImportFilesWorker](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/work/ImportFilesWorker.kt:41) then returns `Result.success()`. Failed items can therefore yield a successful worker state. Chur already rethrows cancellation and records typed refused outcomes in [importItem](/Users/npochaev/GitHub/Chur/shared/app/src/commonMain/kotlin/dev/po4yka/chur/app/ChurController.kt:1993).
2. **Remove-source before catalog commit.** AstraCrypt [ImportUseCase](/Users/npochaev/GitHub/AstraCrypt/features/files/domain/src/main/java/io/gromif/astracrypt/files/domain/usecase/actions/ImportUseCase.kt:61) writes bytes and a preview, deletes the source at line 66 when `saveSource` is false, and inserts the catalog row at line 78. A later insert failure can leave deleted source data and an unindexed vault object. Its [ViewModel](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/FilesViewModel.kt:104) defaults `saveSource` to false. Do not carry this sequencing or default into Chur.
3. **Persist private input paths without a separate lifecycle design.** AstraCrypt [ViewModel](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/FilesViewModel.kt:110) serializes selected URIs to a file and passes the file path to the worker. Chur's [import contract](/Users/npochaev/GitHub/Chur/shared/app/src/commonMain/kotlin/dev/po4yka/chur/app/ChurController.kt:1921) keeps selected inputs in the host only for the call. Worker persistence would change the privacy and permission model and needs explicit requirements.
4. **Treat source modification time as capture time.** AstraCrypt [FileUtilImpl.creationTime](/Users/npochaev/GitHub/AstraCrypt/features/files/data/src/main/java/io/gromif/astracrypt/files/data/util/FileUtilImpl.kt:40) uses `lastModified()`. This is a source timestamp, not proof of when media was captured. Chur should keep its explicit capture-time semantics.
5. **Unbounded parallel item launches or hidden partial failure.** AstraCrypt [ImportUseCase](/Users/npochaev/GitHub/AstraCrypt/features/files/domain/src/main/java/io/gromif/astracrypt/files/domain/usecase/actions/ImportUseCase.kt:33) launches one coroutine per path. The worker uses a dispatcher with `limitedParallelism(4)`, but the use case has no explicit in-flight item budget. Do not treat dispatcher thread parallelism as proof of bounded concurrent resource use. Keep Chur's sequential import until measurements justify a bounded queue.
6. **External viewer as a private viewer.** AstraCrypt [BrowseActionsFactory](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/model/action/factory/BrowseActionsFactory.kt:23) routes opening through private export, then [FilesExportScreen](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/export/src/main/kotlin/io/gromif/astracrypt/files/export/FilesExportScreen.kt:46) uses `ACTION_VIEW` with a URI permission. This grants another app plaintext access. It is an explicit export use case, not a substitute for Chur's protected viewer or range playback.
7. **ZIP concatenation presented as protection.** [CombinedZipWorker](/Users/npochaev/GitHub/AstraCrypt/features/lab-zip/presentation/src/main/java/io/gromif/lab_zip/presentation/work/CombinedZipWorker.kt:67) copies a carrier file and appends an ordinary ZIP stream. That code path is not encryption and supplies no evidence of forensic concealment. Do not add it as a Chur security feature.
8. **Crypto choice as the normal vault experience.** AstraCrypt's Tink Lab and AEAD settings are useful experimental tools, but user-selected algorithms, raw keys, and associated data would add failure modes to Chur's fixed contracts. Do not introduce multi-encryption as a claimed security improvement without a defined threat, versioned protocol, and independent review.
9. **Success messages from job completion alone.** AstraCrypt [ItemActionsFactory](/Users/npochaev/GitHub/AstraCrypt/features/files/presentation/files/src/main/kotlin/io/gromif/astracrypt/files/files/model/action/factory/ItemActionsFactory.kt:19) attaches success messaging through `invokeOnCompletion`. Completion alone does not establish successful work. Preserve explicit success, partial failure, and cancellation outcomes in Chur.

## Architecture, dependencies, and verification value

AstraCrypt's dependency catalog lists Kotlin 2.2.20, Room 2.8.0, Paging 3.3.6, Coil 3.3.0, WorkManager 2.10.4, Tink 1.18.0, and Hilt 2.57.1 in the [version catalog](/Users/npochaev/GitHub/AstraCrypt/gradle/libs.versions.toml:1). Keep Chur's Rust crypto/catalog and Kotlin Multiplatform boundaries.

For example, [DefaultSearchStrategyTest](/Users/npochaev/GitHub/AstraCrypt/features/files/data/src/test/kotlin/io/gromif/astracrypt/files/data/repository/search/DefaultSearchStrategyTest.kt:22) checks cache calls using mocks. Before implementing an opportunity, use focused acceptance checks: cancel and lock during the operation; source and destination provider refusal; malformed or oversized artwork; duplicate album/file names; partial export cleanup; and process recreation. A notification-only change and a restartable job system must have separate acceptance criteria.
